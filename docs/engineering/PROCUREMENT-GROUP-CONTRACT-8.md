# Two-stage regional procurement interface

Approved implementation scope: extract the existing single-agreement authorization from `reviewRegionalAgreement` in `98-trade-ui.js` into one authoritative helper shared by the UI and grouped orders. Preserve ordinary pricing, dispatch, cargo ownership, funded settlement and cancellation liabilities.

Suggested contract:
- `reviewRegionalProcurement(spec)` is a pure two-stage review returning both ordinary contract forecasts, aggregate commitments, risk/capacity disclosures and a review token tied to town identity/day/relevant balances, inventory, reservations and market/route conditions.
- `authorizeRegionalProcurement(review)` recomputes both stages without mutation, checks token, finite bounded quantities/dates, distinct stage indexes, both ordinary eligibility rules, combined active-slot limit, combined output reservations and shared loading/market/wharf capacity. Only then allocate IDs and append both contracts plus their group record in one synchronous commit. Failure leaves serials, arrays, wallets, reservations and RNG unchanged. Never temporarily append stage one to validate stage two against live state: use an explicit candidate commitments argument or independent candidate calculation.
- Keep existing contract records as settlement authority. Optional `procurementGroup` / `procurementStage` references must resolve uniquely; a bounded optional group collection contains IDs, reviewed creation day and stage windows. Legacy ungrouped contracts remain valid. Pruning contracts must preserve active references or explicitly retire completed group history.
- Future stages need explicit dispatch eligibility/window checks. Reserving the same stock or throughput twice is forbidden; disclose that future production is a forecast, not guaranteed inventory.
- Cancellation stops future dispatch through the existing authoritative contract cancellation path. Travelling cargo, regional claims, fees, payables and eventual arrival/return continue under existing ownership and settlement. No deleting liabilities, fabricated refund or free reward.
- Group outcome derives from its contracts/actual successful deliveries. Cancelled, returned or removed shipments cannot count as fulfillment. Bounded outcome UI may explain partial/late/failed milestones without granting a bonus.

Before integration require: stale quote and second-stage failure atomicity; repeat-click exactly-once authorization; overlapping good/producer/route capacities; cancellation before/between/after stages; travelling cargo closure/return; malformed group imports and legacy saves; exact conservation and continuation/RNG. The economics worker owns implementation; integration lead owns reconciliation. This interface approval is project implementation guidance, not a release-quality claim.

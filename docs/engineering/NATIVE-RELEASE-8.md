Actual Android game evidence is fixed to integration `03cb54675880a9b60c0c8d8de5dd0b671d0abff3`, assembled JS SHA-256 `27ca5f1e1e5df352d38daf042d2de63b63024b8deed596c79e2f4679cc50947e`, plus the scoped native export-cleanup fix. The later package checkpoint is `31987fcbe108e9d9cb8ed7ce4155f51cd234ba62`, JS `d90bb509173a803b75c3cdc432fea57ce2f1e2abbcb13b8886c56d8feaffe515`; it has a separate clean SDK build and package verification, **not a later emulator run**. Both use development 8.0.0 / code 22 / schema 8. Native work changes no save schema or JS bridge contract.

The host now deletes its privately prepared export and clears its filename if launching a document chooser fails. SDK discovery sorts versions numerically, avoiding android-9/build-tools 9 taking precedence over 36. Build reports distinguish generated development signers from caller-supplied signers. The package verifier also rejects all three private instrumentation/provider classes.

Actual API-30 Android / WebView 83.0.4103.120 results are in [the curated receipts](../previews/native-8/evidence.json):

- Sixteen host/provider checks passed: real external ContentProvider Unicode/BOM import, malformed and over-8-MiB rejection, export truncation, cancellation cleanup, acknowledged Back/save failure/timeout/stale replies, supported renderer termination, recreation with retained file-origin storage and acknowledged exit.
- Three actual DocumentsUI checks passed: import chooser background/cancel/resume and export cancellation surviving Activity recreation with private prepared-file removal. Successful transfers were tested through a separate actual Android provider and Activity results; successful file selection through DocumentsUI itself is not certified.
- The full unchanged game founded a town through framework touch, painted 3,315+ sampled colors, advanced three settlement days, opened six panels and handled native Back through a confirmation and underlying drawer. That flow's later driver failure is retained rather than relabeled a whole-run pass.
- A subsequent focused native run passed real Vorbis playback, on-device suspension-save completion, a running clock stopping, observed Overview DOM/paint/storage work parking during native pause, resume without a backlog burst, preserved user pause, full-game archive roundtrip, two simultaneous streaming crossfade decks, retirement/unloading of the old source, and synthetic 2,000-resident load/validation with continuing soundtrack playback. No captured JS errors occurred. Actual onPause made `document.hidden` true; the still-visible suspension variant has separate host/performance-owner evidence.

The emulator used official SDK tools, API-30 AOSP x86_64, TCG without KVM, two guest cores, 2 GiB RAM and 640×360 at 160 dpi. Boot took about 383 seconds. A boot SystemUI ANR overlay blocked the first picker probe. One ordinary Wait action removed it; later real picker input passed. No root or security-setting changes were used, and no repeated ANR-dismissal loop was run. The emulator and local debug forwarding were stopped after evidence capture.

Native PSS snapshots were about 91.3 MiB for the app/browser at the map stage and 93.0 MiB at the 2,000-resident/audio stage. The observed WebView sandbox was about 138.8 and 160.9 MiB respectively. Sandbox processes are reported separately; these are timed snapshots including probe overhead, not peak-memory, physical-device or FPS certification. The [native canvas capture](../previews/native-8/native-game-map.png) is actual Android rendering of a newly generated test town, not a host-browser mockup.

Negative evidence also remains in the receipt. Combined regional founding/30-day and synthetic reset/construction/load calls exceeded a 90-second callback budget under software emulation. Separating the latter operations produced a completed 2,000-resident load, not a sustained throughput result. The crossfade driver initially toggled an already-open Settings drawer closed and targeted its hidden button; visibility/hit-target checks and idempotent Settings opening fixed the driver. Initial music remained paused at time zero after expensive founding; an explicit trusted Next touch started playback. Automatic first-founding audio should still be checked on a real device.

The [reproducible scratch builder and native probes](../../tests/android/README.md) use disposable signing keys outside the repository and test-only APKs. Exact installed target assets/DEX/manifest and instrumentation APK identities were checked. Public 7.1.1 and the early integration APK share a certificate; disposable scratch signers differ and cannot update those installations. The private persistent signer remains with the integration lead.

Host-JVM archive/Back tests, generated Back JS waiting for storage commit, real-browser ten-track decoding/playback, media promise races, older-API/layout fallbacks and native-JS clock/pause regressions also passed with their own source bindings. They supplement the native results above. API 24/33/36 runtime, physical FPS/thermals, listening/speaker quality, audio-route interruptions, full app-process death/Continue and successful picker file selection remain unverified. No release was published and no production signing key was read or copied.

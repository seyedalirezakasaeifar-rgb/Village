# Regional camera locator

The existing map had zoom, center, district-deed previews and a waterfront visit action, but lacked a persistent overview of the current viewport within the 128×128 region. The new map-shaped control opens a compact optional locator beside those controls. Tap anywhere to move the camera without changing zoom; focus the locator and use arrow keys to pan or Escape to close. Existing focused district bounds are shown in gold. Port/fishery and station/depot symbols distinguish useful infrastructure, with a small legend. No additional governance panel or economic feature is introduced.

Owned runtime file: `src/98zzzzzzzzz-region-locator.js`, plus assembled `assets/game.js`. Sequential base is `b5aeb837`; integration already containing that commit should cherry-pick only this locator commit.

The locator reads the renderer's retained bitmap, world dimensions, immutable district geometry and static `displayItems` snapshot. It never calls the cooperative economy, place-state initialization, routing or agent APIs. The overview and bounded infrastructure sample rebuild only when groundRevision or the retained static-scene identity changes, including construction/demolition. Camera repaint only copies the small overview and draws bounded symbols, district focus and viewport rectangle. Closed locator returns immediately. It introduces no timer and is compatible with paused/reduced-motion play. Integration must preserve the existing rule that the retained static render snapshot is committed before publication; no new partial-day access is added here.

Two 392×208 canvases consume 652,288 backing bytes total, independent of atlas dimensions and zoom. Up to 96 infrastructure markers are retained; buildings are rasterized into the small overview once per scene revision. This is an orientation map rather than a second inspection UI. Existing district labels and named-place visits continue to provide detailed selection.

`tests/test_region_locator.py` exercises actual toggle, tap, arrow-key and Escape controls at 844×390, verifies screen reachability and unchanged save state, captures the visible mobile controls, and measures 200 near/far locator redraws. On host Chromium both averaged 0.0075 ms of JavaScript/canvas submission per update, with zero overview rebuilds during camera-only updates. This is not an Android FPS measurement. Exact source hash and screenshots are in `docs/previews/region-locator/`.

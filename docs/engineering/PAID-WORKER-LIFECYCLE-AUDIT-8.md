## Reproduced handoff blockers for worker owner

1. `adapter.js workerRequest('step')` does not consume `command`. Two sequential same-epoch/same-ID requests advance two days. Add step and every admitted mutator to one safe-integer request sequence, consumed before model admission and never financially rolled back. Reject unsupported/duplicate paid DTO envelopes before dispatch. Do not maintain a second sequence in paid layer.
2. `load` bypasses epoch comparison. An old epoch0 load adopts over epoch1 and increments to2. Adoption must compare the expected current epoch, including initial0, and serialize with outstanding stepping/save/adoption. Do not accept stale adoption merely because its payload is valid.
3. `workerSnapshot` drains outbox. Concurrent export during an async step consumes its committed council-event; the main export adapter discards outbox, final step response is empty and pendingEvent remains open only in worker. Inspect also ignores response effects. Reads must not steal command-owned effects: either nondestructive reads or a single deliberate effect-delivery channel with identity/ACK. This is already possible without speculative partial days: the test exports after a committed tick's task yield.
4. Old worker `choice` is its own unprotected financial dispatcher. A controlled source callback transferring7 and then throwing leaves treasury93/region107 from100/100, with command consumed. Replace this settlement path with the shared paid dispatcher; do not run both. This is a known composition gap, not evidence that the disabled worker is shipping.
5. Shared-root requestSave publishes in a microtask. Building the reply/snapshot immediately after run misses the save-request; it appears only in the subsequent drain. Await the completed root's existing save promise/drain BEFORE snapshot/outbox publication. Do not call requestSave again as a flush: outside-root calls may initiate a second write.
6. Configuring generation with browser saveEpoch permits an old root save to execute after worker load: test dispatches save in epoch2 and resolves true. Configuring with workerEpoch cancels it false with zero writes. The adoption owner must invalidate the shared generation at load/restore and drain/abort prepared work before adoption. A save-request is intent; only real owner persistence plus matching ACK is durable success.
7. `archive-endpoint.js submit` keeps the caller's request object by reference. Mutating accepted `{id:1,op:'export'}` to id2/restore before its queued task executes performs restore, completes id2 and leaks active id1. Copy validated scalar request fields at submission; bind accepted ID/epoch/operation to immutable local state. Never reread caller-owned fields after acceptance. A mutable epoch can similarly evade queued stale checking.

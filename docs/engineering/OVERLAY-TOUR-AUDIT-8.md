# Overlay transition tour

Automated Chromium audit of repeated overlay, zoom, camera, lighting, quality, motion and viewport transitions on the 2,000-resident / 21-deed / three-route fixture. Run with `python tests/test_overlay_transition_tour.py` from the repo root. The tour holds simulation paused; five actual simulated days prepare dated incident records, then all visual transitions are render-only.

It performs 96 transitions (eight passes over roads, business, hardship, recorded crime, land, bus/metro transit, health and school access, neighbourhoods, deed boundaries and no overlay), rotates four landscape/portrait layouts, zooms between near and distant LOD, alternates day/night, and toggles low/high quality and reduced motion. Every step checks legend content and single-node identity, state and RNG purity, stable repeated paused pixels, and atlas/repair-cache limits. The final full cache invalidation must reproduce exact canvas pixels without changing state/RNG. Controls/legend layout is additionally checked by `tests/test_overlay_legibility.py` at four mobile sizes.

Results for source SHA `6260809a99d39d3f3c8131bcd9e85343695617d5629950409cca1ba7ef2aa1aa` are in [tour.json](../previews/overlay-tour-8/tour.json). All 96 transitions completed without browser errors. The Town Signals key stayed at one node, document node count stayed exactly 406, post-GC Chromium heap remained 14.3 MB from start to finish, peak art atlas was 10.09 MB, and night emission cache peak was 2.20 MB (at DPR 2). Pause redraws were stable and cold reset matched pixels and preserved game/RNG state. No stale marker accumulation, ghost actor, or cache growth reproduced. Captures are raw map-canvas pixels, without browser-harness save notices.

# Existing creator-cap preflight — local production patch

This patch uses existing legacy admission limits: 8,000 person records, 3,000 household records and 3,000 firm records. Historical identities count; none are deleted or compacted. It requires no experimental codec, schema change, day wrapper or transaction owner.

Pure creatorCapacityReason checks run before firm construction charges/IDs/RNG, private-enterprise and airfield proposals, retail proposal work, and scenario firm financing. Firm/airport projects reserve their future firm slot; direct construction respects those commitments. Private-service creation checks before its construction contract and escrow. Existing closed-provider recapitalization remains allowed because it adds no identity. createFirm additionally rejects before touching a building as a last-line invariant; known paying callers are guarded earlier.

Project completion checks actual firm count before constructionWork, countdown, project removal or capital transfers. An already-overbooked imported site retains its building, project, escrow and remaining days and exposes the capacity reason. The explanatory project reason may change; money, IDs, RNG, goods and commitment remain. No unsupported forced refund or deletion is performed.

addHouseholdAt checks the complete proposed family size and household slot before profile RNG or transfer. It defers the entire proposed household rather than splitting it. birthsAndGenerations checks each prospective child before its random decision and stops at the final slot. Family arrivals and household formation return before selection/RNG or savings/member movement. Empty estates and deceased identities remain. Community displays reached limits; paid construction and retail return a concrete refusal. These are narrow growth deferrals, not pausing the whole simulation.

The direct creator inventory covers all production G.people/G.households/G.firms push sites except bounded fresh-world seeding in 20-world, whose authored population/firm counts are far below these limits. Waterfront setup already checks createFirm success before taking capital; scenario financing now preflights. Household arrival callers may still perform independent project completion or vacancy review work before asking for a household: the caller's legitimate existing action is not rolled back, and the new house can remain vacant. Other automatic daily effects and RNG remain ordinary simulation effects, not globally transactional.

## Evidence

Executable tools/test_creator_capacity_preflight.py covers cap refusals with complete archive/RNG equality, reservations, old overbooked project preservation, controlled actual birth 7,999→8,000 and actual firm 2,999→3,000 with self-import. A 90-day paired archive replay against pre-patch source is exact. The controlled birth fixture adjusts eligibility and draw; it is not a naturally observed 8,000-person city. A valid synthetic retained-firm fixture establishes the current import boundary. 10,000 pure household checks cost approximately 0.4–0.5 ms on the host. No full graph cloning/certification is added to ordinary days. Native performance has not been measured.

Current paid 7233d8d composition council suite finished successfully: all 60 choices preserve exact model/RNG/normalized reload/receipts under the actual experimental full owner. This is compatibility evidence, not permission to activate that expensive owner.

## Deliberate limits and stable-release owner decision

This does NOT prove total bytes/nodes, arbitrary string/numeric/history growth, loans/freight/transit/project/other validator caps, native storage quota or future-field admission. Those systems retain their current independent protections; this patch makes no new global guarantee. Existing already-oversized archives are not repaired. At retained identity capacity, growth is explicitly deferred indefinitely until a separately reviewed archival/recovery feature exists. Normal services, trade, existing families and businesses continue; long-session capacity remains a documented limitation.

The shared root protocol is codec-independent, so a worker can in principle use a paid-command-only owner without schema9: capture full graph/runtime once per paid command, run only an enumerated trusted DTO command, defer saves/UI/outbox, certify using current legacy import and accounting rules, then commit or restore descriptors/keys/identities directly. Nested commands join one root. Unknown commands fail closed. This can truthfully promise atomic command model/RNG/receipt rollback and deferred single-save publication for tested commands. It cannot promise incremental/constant-time cost, protection of automatic days or later visual growth, storage durability before acknowledgement, or all creator/string/byte budgets. A bounded partial snapshot is unsafe without an exhaustive write/reference proof, including raw aliases. No production-ready legacy owner is delivered here; current experimental automatic adapter still uses schema9/full normalization and must remain disabled. Paid-only full snapshots may be tolerable because commands are infrequent, but require separate host/native measurements and lifecycle corpus before activation.

Publication remains paused. All work and synthetic summaries are local; no GitHub retry occurred. Two early harness revisions used an unavailable validator helper and evaluated a closure-local function externally; these failed before receipts were emitted and were corrected without changing application assertions. Initial reservation test also omitted already-committed slots; corrected fixture respects them.

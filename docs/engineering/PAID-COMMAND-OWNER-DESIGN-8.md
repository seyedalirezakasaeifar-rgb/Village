# Bounded paid-command owner decision

Reviewed public shared API4ee829c, current paid layerbb58ac3 and worker459d750d. Recommendation: a paid-command-only transaction owner is feasible with explicit scope integration; the reference owner is not promotable. Do not activate a replacement by merely skipping worker day admission. No new controller, proxy, journal, hydration commit or schema9 certificate is needed.

## Immediate integration blockers

1. `experimental/worker/paid-worker.js workerTickCommittedDay()` currently starts shared `kind:day` whenever an owner is enabled. A paid-only owner must instead leave synchronous tick on its existing completed-day failure/save fence. Owner scope must be explicit (`paid-command`), not inferred from a missing hook. The worker owner owns this change.
2. `experiments/paid-command-root.js completeDevelopmentProjects` unconditionally starts a command root whenever enabled, including every automatic tick with zero due projects. Skipping the worker day root alone still causes daily snapshots. Its automatic-tick call must follow the ordinary day path; explicit player completion or completion nested in an admitted paid command still joins that command. Distinguish trusted execution scope, not whether an arbitrary callback happens to create something. A UI command during automatic work must remain queued/refused, never inherit a bypass. This paid-layer change belongs here once the shared scope contract is agreed.
3. Worker `step` may yield only between completed ticks. Paid packets must refuse/queue while `workerStepping` is true, including between days; otherwise a multi-day batch interleaves player mutations and loses its replay contract. Load already refuses that state. Snapshot/export remain completed-state operations.

## Minimum owner contract

Use the existing single `__capacityAdmissionProtocol.shared` and runtime registry. Register paid runtime plus worker outbox/event serial/version/prepared token while disabled and idle. Capture at the outermost allowlisted player command only: original `G` reference, synchronous busy flag, every registered runtime capture, and `graphSnapshot([G,...runtime])`. Capture each runtime once. Enter marks trusted command scope/busy; nested work joins existing root. On refusal/error, restore the graph first, reassign original G and runtime bindings, then restore busy/scope. Do not replace G with parsed JSON or invoke hydrateSave: aliases, pending callbacks, cache references, save timeline and RNG must remain exact. A restore failure fences mutation/export and requires recovery.

The full graph snapshot intentionally handles raw aliases without proxies. Costs are paid on occasional explicit commands, never per read/frame/day. Command allowlist initially covers the actually proved authored council choices and school/fire invitations; it must not silently approve the remaining69 controls. Original descriptor validation, costs, creator failure and shared poison semantics remain the model authority. Add operation-specific conservative creator-count preflight BEFORE outer payment; recheck exact array counts after work within the same root. A refusal cannot close a review, retain an investor charge, advance RNG, publish effects or save. Under-limit successful behavior/order remains unchanged. Unexpected callback errors roll back and return explicit failure.

Initial and post-command checks are named structural/count checks, not a general archive capacity certificate: selected legacy schema supported, integral IDs/nextId, finite financial results, affected references/records valid, and existing person8000/household3000/firm3000/loan10000 caps not exceeded. Existing pure validators may be reused after measuring their cost. Do not run normalizers that mutate committed state as certification. A successful trusted mutation plus a few count checks does not establish validity of every possible import field. Stronger generic checks must have explicit scope and evidence. All selected creator branches need exact maximum deltas; do not guess one firm for a callback that can loop over firms or finish multiple projects. A postcheck still provides atomic paid-command refusal, while cheap preflight prevents wasted work and unreachable leaf states.

Model publication stays in the shared outbox. Financial commit precedes view effects; publication errors are separate from the financial result. Queue save through existing shared requestSave once and drain its pending committed intents before snapshot/response. Epoch uses workerEpoch; command/request sequences stay outside financial rollback. Effects use epoch/serial ACK and are never consumed by export. Only the current original storage owner prepares/writes/verifies/ACKs. Failed owner writes can retry a fresh token without replaying the paid command. A committed command with a pending/failed save is not reported as rolled back or durable. Native callbacks must carry session/epoch/request/token/checksum; imports and process lifecycle drain or explicitly fail pending requests and preserve the prior verified save.

Existing ea04b99 proves only reference-owner command composition and lifecycle pieces. It is not acceptance of this production owner.

## Explicit remaining limits and decision

This design cannot solve automatic births/migration/firm creation reaching legacy identity caps, historical arrays/text accumulating, arbitrary archive bytes/nodes/depth, renderer-created persistent traffic, or future creator branches not guarded at their outer boundary. Automatic creators need their own exact no-partial-effect preflights, owned by admission owner. Existing global archive limits and import rejection remain in force; no budgets are raised and no schema9 encoding is enabled. A paid transaction alone cannot guarantee every later town is saveable. Do not ship claims of global capacity-safe admission.

Implementation is deferred pending agreement on explicit command-only execution scope and authoritative creator preflight ownership, plus measured late-command costs. Adding an owner now without those two day-path changes would reproduce the rejected daily cost; silently bypassing guards would create false coverage. This is a precise integration dependency, not an approval request. Once those contracts are published, implement only the bounded adapter/scope hook here and reuse the existing actual-model refusal corpus; worker and native owners retain their implementation ownership.

## Disabled bounded prototype hook contract

`experiments/paid-command-owner.js` installs the one shared owner while disabled/idle. Register worker runtime, then existing paid runtime through `workerInstallPaidOwner(owner)`; worker may attach deferDOM and overrides generation with workerEpoch before enabling. `owner.scope === 'paid-command'`. Worker wraps only the synchronous dispatch call in `owner.withPaidCommand(() => __rootAdmission.dispatchSerializable(dto,context))`, then drains existing saves and publishes its response normally. Worker day dispatch calls `owner.withOrdinaryTick(() => tick())` instead of shared day run. Scope methods never start another root or accept asynchronous work. The paid completion wrapper uses `owner.automaticCompletion(originalWork)` only within this explicit ordinary scope.

IMPORTANT blocker retained: withOrdinaryTick refuses BEFORE the day starts if any development project exists. automaticCompletion allows only the empty-project no-op; otherwise it refuses before constructionWork. Original completion pays for crews/materials, removes projects and debits regional capital before createFirm, and redevelopment can create multiple households/people plus other records. There is not yet a proved local atomic rollback or comprehensive preflight for all those paths. The prototype therefore does not bypass them, silently skip paid construction, or run whole-graph snapshots each day. It is not a playable production replacement until admission/worker owners supply a safe automatic-completion boundary. An adapter implementing that boundary must be separately reviewed before lifting this fence.

Checks are explicit legacy structure/identity counts, affected records/bridge validation and total cash conservation, not a byte/node certificate. Only authored council-choice and private-provider command roots are admitted initially. Counts are checked after work inside rollback protection; authoritative before-payment creator preflights remain an integration requirement, NOT an implemented guarantee. Snapshot, restore and validator durations/graph-row counts are exposed in owner.metrics; metrics never determine financial success. Full runtime alias snapshots and effect/save root handling remain the shared protocol's responsibility. No default startup includes this prototype.

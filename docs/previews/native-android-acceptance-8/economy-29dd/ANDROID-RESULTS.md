# Native economy-tier renderer QA

Source commit `29dd12af7d4aac6b22efcfe1cec1e2d59aff2c1f`; canonical assembled `assets/game.js` SHA-256 `b277816a34f6de3ce3448a459a47630a61ed5e980e5e02f6bae2dcd135c8bd58`. Scratch-only manifest/package and launch query used package `org.townledger.vale.qaeconomy29dd`, URL `?cityArt=webgl&cityQuality=economy&cityBadge=1`. APK SHA-256 `f1d592a094793ecaed28d433b02a72ecd435c27c04338574665bf8b4b96cffcc`.

On API 30 / WebView 83.0.4103.120 (x86_64 software emulator, SwiftShader), the economy renderer initialized and the actual scene showed the synthetic 169-resident town. Runtime reported 21 draw calls and 18,114 triangles. Real Android touches opened the Town Hall inspector, panned and zoomed the map, and paused/resumed simulation. While paused the WebGL frame count stayed fixed for 10 seconds. Camera gestures preserved the complete save hash. Controlled `WEBGL_lose_context` triggered the visible `Canvas fallback · 3D released`; the WebGL canvas was removed and the original Canvas remained. The paused save hash was identical across context loss.

Additional settings-path check: removed the forced `cityQuality=economy` test query without reloading, then used the actual Graphics quality select to choose Performance and Balanced. Performance retried 3D successfully. Balanced triggered the automatic software-renderer policy and visibly fell back with `QA · Canvas automatic fallback · Software renderer capability`; `__cityRendererFallback` reported `{quality:"canvas", automatic:true, reason:"Software renderer capability", backend:"Android Emulator OpenGL ES Translator (Google SwiftShader)"}`. The preference remained Balanced. See `economy29dd-auto-canvas.png`.

Resize check is incomplete. A temporary emulator logical-size override to 800×450 changed Android configuration from `sw360dp`/640×360 to `sw450dp`/800×450, then back. The isolated app process PID and ActivityRecord remained the same; logs show configuration changes but no process exit or ANR. The page returned to Welcome with Continue available and a stored `townledger-v6` save envelope (376,381 bytes), so the town checkpoint remained present. The launch URL was restored, indicating WebView/activity content reinitialization; `MainActivity` declares `screenOrientation=landscape` and handles orientation/`screenSize`, but not `smallestScreenSize`, making Android configuration recreation the likely cause. Lifecycle callbacks were not instrumented, so recreation versus WebView reload is not conclusively distinguished. The display override was restored to 640×360. No resize acceptance is claimed. The renderer module also took minutes to initialize on this software emulator, and interaction responses were slow. These results do not establish physical-device performance.

After the recreated page loaded, local storage reported graphics quality `low`; therefore persistence of the just-selected `Balanced` preference across this configuration change is unresolved, despite the immediate Balanced selection having shown automatic Canvas fallback. Do not treat that setting as a persistence pass.

All images depict a synthetic QA town. No raw state snapshots, APKs, signing material, user saves or personal data are included. No source edits were made for this QA build.

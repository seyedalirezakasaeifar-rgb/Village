# Experimental worker ownership contract

Base production ca0c6d07. Not enabled or approved for release.

- Worker alone owns G/RNG. UI snapshots are immutable completed states. Main may own camera, selection, draft form values and visual actors; it cannot write authoritative fields. Real map currently needs a full schema. The small projection schema is sufficient only for the earlier test screen; graphics owner must specify a complete view schema plus geometry revision before lowering real-view cadence.
- Request: id (transport correlation), epoch, monotonically increasing command for mutations, type, payload. Reply: id, ok, completed snapshot/result or explicit error. Snapshot includes epoch, command, committed-day version/day, RNG, model or projection marker, ordered outbox and optional profiling. A projection must never be applied to the current real renderer as if it were a canonical model.
- Mutations: policy(key,value), build(kind,x,y), review(index), choice(eventId,index). inspect(building) is read-only. Unsupported direct transactions reject. Repeated commands and stale epochs/event IDs reject. Council callbacks remain worker-local; only opaque IDs and descriptions cross messages.
- load(archive) advances epoch, clears pending event/save transactions and invalidates running day batches. New-town must generate a new authoritative worker archive before this same load barrier; existing main-thread seed/start handlers are blocked in the bridge. No background auto-fallback may continue a stale main G after worker error.
- step(days) advances complete days and yields tasks only at commit boundaries. Commands wait for an atomic day; monthly-day acknowledgement can still exceed200ms. Manual real-view proof stays paused and does not claim a realtime speed. A release admission owner must supply requested/actual committed-rate/backlog accounting before enabling autoplay. Synchronous production remains unchanged and available by ordinary startup; experimental mid-session fallback requires a completed canonical export/load, not a stale snapshot.
- Outbox notification/ambience/header/panel invalidation/council-open/council-close/save-request effects are explicit. Save-request is an intent: real-view bridge displays it pending until acknowledged Save test slot. It does not silently call production save. Unknown effects throw visibly. No callback crosses the boundary.
- save-prepare pins one canonical archive/token/epoch/day/version/command/checksum; main owns one write and exact readback before save-ack(token,checksum). Duplicate/stale ACKs reject; save-abort releases a failed preparation. load invalidates it. Worker never writes storage. Existing production save envelope chronology, visual-state composition, crash retry and root transaction rollback are NOT yet integrated. Save/admission owners must provide these contracts before promotion.

## Real view proof and completion limits

Inject real-view-bridge.js inside the game closure (test-only), then enable with generated worker source and archive. It replaces the synchronous frame entry with paused readonly drawing, routes actual construct through worker, and provides explicit day/wage/petition/test-save controls beside the real canvas. Unsupported production buttons visibly reject. The test uses real renderer and real construction/council functions, immutable dense snapshots, trusted button clicks and actual test-key persistence.

This is a paused integration proof, not complete gameplay. It intentionally does not enable realtime admission, automatic saving, arbitrary policies/imports/trade/renewal/service controls or native lifecycle. Real building pointer placement and all keyboard/file-input paths need comprehensive admission routing; a capture-phase button guard alone is not a production security or ownership boundary. Frozen snapshots catch nested writes, but every main-thread G replacement must also be audited. Real-renderer cold drawing/panel costs remain material (audit map323ms, agenda359ms). Graphics owner must isolate its caches from authoritative normalization before rollout; bridge reset touches presentation topology only because invalidateRoads currently writes G.roadMetrics.

## Runtime arithmetic admission

runtime-guard.js dynamically checks unsigned shift, signed bitwise conversion and Math.imul around2^31/2^32 before any worker model load/command. `runtime-status` is available without admission for diagnostics. Failure blocks archive parsing and simulation with UNSUPPORTED_INTEGER_RUNTIME; it does not convert, reseed, repair or persist saved RNG. Main is tested before bridge adoption too. Page pass plus worker fail/startup error returns to untouched synchronous production before model admission. Page failure is an unsupported runtime, not permission to run synchronous economics on the same broken arithmetic. Parent/native owner must wire that failure into the application startup gate and supported WebView guidance; the isolated bridge guard does not retrofit all production entrypoints. After admission, worker errors leave the view paused; no stale-main-model continuation is allowed.

The native owner's d399326 report says dynamic operations saturate in worker, page, blank iframe and bare worker. No current evidence here contradicts that diagnosis. Chromium self-test passes; a deliberately injected failed worker rejects load before JSON parsing and keeps epoch0. Native owner must execute the actual guard in its failing runtime and a supported runtime; this host proof is not native acceptance. Original deterministic random() and archive schema remain untouched.
